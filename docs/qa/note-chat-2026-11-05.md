# 0.5.62：管家聊天创建笔记、配图与提醒

2026-11-05，版本 78 / 0.5.62。沿用 `codex/phone-supervision-053` 的现有工作区（HEAD `ede1331`，包含既有未提交改动），没有清理或重置历史工作。

## 直接使用

在本机管家聊天中发送：

> 帮我写一篇介绍深圳咖啡店的小红书笔记，配图，明天晚上八点提醒我。

新流程会使用当前配置的管家模型生成 JSON 标题、正文，本机验证后保存草稿并安排提醒。配图会直接打开系统文档图片选择器，不进入笔记表单重新填写。用户选定一张图片后，通过持久内容 URI 授权保存在草稿中，并在聊天中汇报实际选图状态和提醒时间。

更多支持的命令：

- 生成小红书文案，纯文字，十分钟后提醒我。
- 写一篇小红书笔记，沿用上一张图片，明晚八点半提醒。
- 把刚才的小红书笔记改到明天九点提醒。
- 把刚才的笔记取消提醒。
- 把刚才的笔记改成纯文字。
- 给刚才那篇笔记配图。
- 查看我的小红书定时任务。

“刚才”指本机笔记列表最近保存的那一篇，不是任意聊天里引用的笔记。修改提醒、取消提醒、调整该草稿的图片以及列出本机草稿无需调用写作模型。已经到期的草稿若只改图片，会保留文案并转成无新提醒的草稿；不会重新触发过去的提醒。

## 用户可配置项

入口：管家聊天 → 更多 → 手机操作 → 小红书笔记 → 聊天笔记默认设置。

可配置文案风格、目标读者、默认篇幅（50–2000 字）、配图方式（纯文字／每次询问／沿用最近一次图片）、默认提醒时刻和 IANA 时区。默认时区为 Asia/Shanghai。配置存在手机私有存储中，保存失败会提示。

用户聊天中的明确写作和配图要求覆盖默认值。只有明确要求提醒或带日期的发布安排时才创建提醒；单纯在主题中提到“明天的活动”不会自动安排任务。只说明提醒日期、没给时刻时使用用户默认时刻；不说明日期的时刻按下一个未来时刻处理。

模型沿用管家当前配置，不复制或新建 Key。Pi 配置仍通过已有 Pi 路径生成文案，需要对应电脑在线；直接模型 API 配置不需要电脑。

## 实现与边界

- `NoteCommand` 独立处理意图、时间、默认参数、模型写作提示和响应字段白名单。支持常见的今天／明天／后天、YYYY-MM-DD、HH:mm、上午／下午／晚上、中文数字几点、半点和分钟／小时后的说法。模糊时间、多个日期/时刻、显式过去时间、未支持的周期计划会被拒绝，不让模型猜测后执行。
- 模型仅返回 title/body。模型生成的 URI、id、动作和 dueAt 字段均被丢弃；提醒和图片只能来自用户指令、保存配置和系统图片选择结果。
- 生成、提醒更新均通过聊天现有操作锁及操作轮询完成，不另起普通聊天请求。操作记录标记 phoneAction，防止重新生成按钮重放任务，也不混入普通模型/Pi 历史上下文。
- 图片草稿先保存再打开选择器；取消、失败、等待 90 秒后仍未选择分别汇报，不伪造已配图。后续迟到结果可以写入仍存在且处于 pending 的草稿；不覆盖已选结果，也不重建已删除草稿。
- 新图片需要用户在系统选择器选择一次，不支持全相册静默扫描、按视觉内容自动挑图、AI 生成图片或多图。复用上一张时验证 URI 仍可读取，否则提示重选。
- 列表最多展示最近 20 篇；提醒状态来自本机存储。不能据此证明小红书实际发布成功。
- 仍是一次性提醒和内容交接，不是定时无人值守发布。最终发布在小红书确认。系统调度、通知、锁屏和省电影响与 0.5.61 相同。
- 不支持任意自由表达或所有日期说法。未识别的普通消息仍走已有管家聊天，不能据此声称任务已经创建。
