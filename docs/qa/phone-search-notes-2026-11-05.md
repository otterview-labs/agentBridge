# 0.5.61：手机搜索与小红书草稿、提醒

日期：2026-11-05。版本：77 / 0.5.61。基线为当前 `codex/phone-supervision-053` 工作区，HEAD `ede1331` 上已有改动继续开发。本轮未安装、连接、操作或测试手机，也没有实际发布内容。

## 搜索指令

在本机管家聊天中可以使用：

- 帮我在小红书搜索深圳咖啡店
- 去小红书里搜一下猫咪
- 用小红书查找猫咪
- 搜一下小红书里的猫咪
- 打开小红书搜索猫咪
- search Rednote for cats

这是对常见明确命令句式的扩展，不是无限制的模型规划。沿用本机已安装 App 的名称、包名及已知别名匹配；没有唯一目标时不执行。电脑员工会话、语音通话、普通聊天和重新生成仍走已有路径。无需模型 Key 执行已支持的手机指令。

搜索服务在 20 秒的有效期内尝试打开唯一且明确标记的搜索入口，优先选择有搜索描述、提示或已知搜索输入资源名的输入框，支持时先发送聚焦动作，再填写并核对文字。最后只提交明确的 Search 动作，不触发 Send、下一步或支付操作。只报告搜索请求已提交，不声称已经验证结果。多个不明确目标、过大的页面树、锁屏、失去权限、输入不一致等情况仍停止。

依赖目标 App 提供可访问控件。没有可访问标识、重复搜索入口、复杂嵌套导航及未支持的页面，仍可能需要手动进入搜索页。没有以坐标猜测点击，也不上传屏幕内容。开启辅助功能前的本机说明已包含用户发出明确指令这一触发方式。

## 小红书草稿和提醒

入口：管家聊天 → 更多（⋯）→ 手机操作 → 小红书笔记 · 草稿与定时提醒。

- 保存标题、正文及一张由系统文档选择器选择的本机图片；使用持久 URI 读取授权，不申请整个相册读取权限。
- 支持编辑、删除和一次性本地时间提醒；草稿存放在应用私有存储。
- 提醒通过持久化 JobScheduler 调度，接收开机恢复所需权限；到期将状态转成待发布并尝试发通知。没有后台轮询或常驻扫描服务。
- 通知打开对应草稿，不在后台直接拉起小红书。通知被禁用时，草稿仍可在列表中查看。省电、Doze 或强行停止会影响提醒，不能保证精确到分钟。
- 用户点「保存并交给小红书」后，使用仅指定 `com.xingin.xhs` 的 ACTION_SEND；文字用 EXTRA_TEXT，图片使用 content URI、ClipData 和临时读取授权。
- 不存在兼容分享目标时，说明限制并提供用户点击复制文案、打开小红书的后备方式。图片需用户在小红书中选取。
- 内容交接不会把草稿改成“已发布”；最终发布必须在小红书内核对和确认。
- 本轮没有实现多图、视频、周期任务、自然语言创建笔记日程、无人值守发布或发布回调验证。

小红书还提供[官方 Android 分享 SDK](https://agora.xiaohongshu.com/doc/android)，本轮未引入。现有 Android 分享是否被手机上的小红书版本完整接收，必须后续在真机验收。不得将构建和模拟测试视为已经发布成功。

Android 的[后台 Activity 限制](https://developer.android.com/guide/components/activities/background-starts)是采用通知打开草稿这一方式的原因；[JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler)的调度时机由系统决定。
