# 小镇在手机端独立运行与操作其他 App

评估日期：2026-11-05。0.5.59 已实现用户确定的单次本机操作；自由规划跨 App 任务仍属于后续设计。本轮没有操作或安装到用户手机。

## 当前真实能力

| 能力 | 是否需要电脑 | 状态 |
| --- | --- | --- |
| 手机直接调用自己配置的 OpenAI 兼容模型聊天 | 不需要 | 已有，联网调用服务商 |
| 多套模型配置、收藏、切换 | 不需要 | 本轮实现，密钥保存在手机加密存储 |
| 手机管家最后一轮消息编辑、重新生成 | 不需要 | 本轮实现，本地测试通过；失败保留原记录 |
| 系统 TTS 与已下载 sherpa-onnx 模型的语音识别 | 不需要 | 已有代码；本轮未做语音真机验收 |
| 继续 Codex、Qoder 等桌面工具的原会话 | 需要运行对应工具的电脑 | 现有连接器路径；电脑关闭后不能继续桌面进程 |
| 打开手机 App、输入文字、请求搜索 | 不需要 | 0.5.59 基础版；用户点按执行，输入/搜索需要系统辅助功能授权，本地测试通过，未做真机验收 |
| 任意界面点击、滑动、多步自主规划 | 可设计为无需电脑 | 未实现；本版仅支持明确输入与搜索，不提供坐标/任意点击工具 |
| 完全离线的大模型规划 | 不需要电脑，但需要端侧模型 | 当前未实现；本地语音识别不等于本地大模型 |

## 技术可行性

本地执行器可以运行在安卓设备，模型通过手机直接调用云端 API 返回结构化步骤；电脑、USB 和自建中继服务器均不是这个执行路径的必要条件。Android AccessibilityService 可以在系统授权后读取可访问的界面节点并执行动作、手势，具体支持范围依赖目标 App、Android 版本与受保护视图，不能保证所有页面都可操控。

优先使用 Intent、Deep Link 和目标 App 的公开接口：打开应用、打开指定页面、调起分享或创建草稿。需要跨 App 界面交互时，再单独设计可关闭的系统交互模块；不把无障碍权限、截图读取和通用点击代码混入 WebView 的通用桥接接口。

来源：[Android 官方 AccessibilityService 指南](https://developer.android.com/guide/topics/ui/accessibility/service)。

## 产品与发布边界

Google Play 当前政策明确禁止普通应用通过 Accessibility API 自主发起、规划并执行动作或决策；允许行为遵循静态人工规则的确定性自动化。通用 AI 助手不能仅因支持语音就声明为残障辅助工具。

因此不能把“任意目标交给模型，模型用无障碍自由操作所有 App”当成 Google Play 可直接发布的方案。需要优先评估公开接口与用户定义的固定流程；系统交互实验模块的分发渠道与目标用户应另行确定。

来源：[Google Play AccessibilityService 政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)。

## 建议的后续开发顺序

1. 在手机管家增加可枚举的本机能力，例如打开已选 App、调起指定页面、生成并预览分享草稿。通过受约束的工具参数调用现有系统接口。
2. 引入手机任务状态机：待执行、执行中、等待用户、失败、完成；用户可随时停止。每一步依据实际执行结果前进，不以模型的文字“完成”作为验收。
3. 将固定操作流程做成按 App 适配的任务插件。每个插件有明确目标包名、动作范围、超时和结果检查，前台展示当前执行步骤。
4. 若确需研究界面交互，独立评估无障碍/截图授权、目标 App 可访问性、屏幕锁定与系统版本，先选一个简单场景验收，再决定分发方式。
5. 最后评估端侧大模型。云端规划下手机主要承担语音与动作执行；端侧规划则需要单独测试内存、发热、电量和识别准确率。

建议先选择一个窄场景，例如“打开某 App 并准备搜索内容，停在结果页”，而不是立即承诺任意 App 的完全自动驾驶。

## 已落地的第一版

「管家聊天 → 更多（⋯）→ 手机操作」提供本机 App 列表、打开、输入及搜索。一次固定操作 20 秒自动停止，识别不明确时交还用户。本版不需要模型，也未将跨 App 操作接入模型自动工具调用。完整边界及验收材料见 [0.5.59 验证说明](qa/phone-actions-2026-11-05.md)。

## 0.5.60：从聊天提交固定手机指令

手机管家聊天已支持「打开微信」「打开浏览器搜索天气」「打开便签输入内容」及对应英文固定语法。唯一匹配时自动执行，缺少权限或 App 重名时在聊天说明。无需模型或电脑，尚不支持任意目标自主规划或跨多页导航。操作结果保存到本机聊天，但不用于模型/Pi 上下文或重新生成。详见 [聊天指令与验收说明](qa/phone-command-chat-2026-11-05.md)。本轮仍未进行手机测试。

## 0.5.61：搜索句式与笔记提醒

已扩展「帮我在小红书搜索…」「去小红书里搜一下…」等明确命令，搜索步骤优先定位搜索输入框。手机操作面板增加小红书文字/单图草稿、一次性定时提醒及 Android 分享交接。定时为系统调度的提醒，用户打开草稿后交接并在小红书确认发布；没有实现无人值守发布或周期任务。仍不是任意 App 的模型规划执行器。

范围、132 项本地测试及未做真机验收的限制，见 [0.5.61 验证说明](qa/phone-search-notes-2026-11-05.md)。

## 0.5.62：聊天编排笔记与提醒

本机聊天可调用当前管家模型写标题和正文，直接保存草稿、打开系统图片选择器并创建一次性提醒。支持修改最近保存笔记的提醒或图片、取消提醒和列出提醒；配置风格、读者、篇幅、配图策略、默认时刻与时区。模型不决定 URI、提醒时间或发布操作。

这条路径不等于无人值守自动发布，生成文案需要已有可用模型，Pi 运行时仍依赖电脑。143 项本地测试通过，未操作手机、未真实模型调用、未实际发布。详见 [0.5.62 范围和验收](qa/note-chat-2026-11-05.md)。
